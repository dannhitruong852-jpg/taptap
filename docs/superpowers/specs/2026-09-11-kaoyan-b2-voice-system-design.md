# 考研英语真题 B2 表演式朗读系统设计

日期：2026-09-11
状态：设计已在对话中确认，等待用户对书面规格最终复核
目标项目：`kaoyan-reader-v1`

## 1. 目标

为考研英语真题阅读网站建立一套低成本、可长期扩展的表演式英语朗读系统。系统采用 B2 模式：同一篇文章允许按场景换演员，必要时允许在同一句内部按旁白/对白切换演员；整体接近克制的有声书，而不是广播剧。

核心目标：

- 美音为主，少量英音。
- 英语学习准确性优先于戏剧效果。
- 发音、词重音、句法停顿必须稳定、清晰。
- 表演应根据文章背景、作者态度、人物和场景变化自动调整。
- 网站播放阶段不实时调用 TTS；音频全部预生成。
- 不使用 Google API，不依赖按字数/按分钟计费的商业 TTS API。
- 运行时 TTS 调用成本目标为 0；仅接受离线生成所需的算力、存储和网络传输成本。
- 真题数据、导演结果、演员配置和声音引擎相互解耦，方便未来替换模型而不重做内容层。

## 2. 内容数据与声音系统解耦

真题以结构化数据导入，而不是把每篇文章硬编码在网页中。

建议层级：

`年份 -> 题型 -> 文章/Section -> 段落 -> 句子 -> 句内片段`

每个句子/片段至少保存：

- `text_en`
- `text_zh`
- `vocab_annotations`
- `article_context`
- `scene_id`
- `speaker_role`
- `actor_id`
- `emotion`
- `intensity`
- `rate`
- `audio_path`
- `generation_version`
- `generation_fingerprint`

未来新增年份只导入数据并生成新音频，不需要重新设计网站。

## 3. B2 换声规则

### 3.1 主旁白稳定

每篇文章先选定一个主旁白。普通正文不因为一句话情绪略有变化就更换演员，而是在同一演员内部改变表演状态。

### 3.2 场景换声

只有在存在明确场景或角色变化时才切换演员，例如：

- 进入故事/案例中的人物对白；
- 明确的问答；
- 明确引用某一人物的话；
- 需要角色身份来形成幽默或反差；
- 文章本身存在多个叙事角色。

### 3.3 句内换声

允许一句话内部切换声音。示例：

`“Oh, that’s God,”` -> St. Peter 角色演员

`came the reply,` -> 主旁白

`“but sometimes he thinks he’s a doctor.”` -> St. Peter 角色演员，冷幽默状态

### 3.4 防止过度表演

- 一般文章最多使用 3-4 位演员，除非原文本身有多人对话。
- 同一角色在同一篇文章中必须保持同一 `actor_id`。
- 不为“炫技”强行换声。
- 强情绪必须有明确文本依据。

### 4.2 使用层级

- 主力旁白：01、02、03、04、05、07、08、10。
- 特殊正文：06、09、14、15。
- 角色演员：11、12、13，以及必要时由主力演员兼任特定角色。

演员不是轮班制。导演根据题材、作者态度、叙事方式和当前场景选角。

## 5. 表演状态

所有演员共享 8 个核心状态：

- `neutral`：平静自然，默认。
- `warm`：温暖亲切。
- `lively`：轻快活泼。
- `serious`：严肃克制。
- `curious`：好奇、疑问、探索。
- `ironic`：反讽、冷幽默。
- `tense`：紧张、冲突、突然变化。
- `emotional`：明显情绪加强，供少量悲伤、感动、惊讶等场景使用。

每个状态再带 3 档强度：

- `0`：几乎不表演；
- `1`：自然表达，默认；
- `2`：明显表演，仅用于明确对白、笑点、强转折等位置。

演员身份必须稳定：情绪变化不能让同一演员听起来像另一个人。

## 6. 参考声纹包

正式第一代演员库目标约 65 段参考音频，可扩展到约 80 段。

不是 `15 人 x 8 情绪 = 120 段` 的穷举，而是为每个演员准备少数关键表演锚点，再由声音模型完成强度、节奏和表达变化。

建议配置：

- 主力 8 位：每人约 5 段，约 40 段。
- 辅助正文 3 位：每人约 3 段，约 9 段。
- 角色型约 4 位：每人约 4 段，约 16 段。

总计约 65 段起步。

每位演员至少有：

- `neutral` 基准片段：15-25 秒；
- `expressive` 表演片段：10-20 秒；
- 需要时增加 `serious`、`warm/lively`、`ironic/tense` 或角色专用片段。

音源质量要求：

- 英语原声优先；
- 单人近距离讲话；
- 无背景音乐或几乎无背景音乐；
- 无掌声、主持人插话、多人重叠；
- 低混响；
- 不选极端喊叫或耳语作为基准声纹；
- 一旦演员参考包定型，不随意更换，避免跨年份音色漂移。

## 7. 声音引擎

采用方案 B：**Chatterbox 单引擎**。

不引入 Kokoro 作为正式链路依赖。声音生成统一通过 Chatterbox 完成，以减少多引擎差异和维护复杂度。

原则：

- 本地/离线批量生成；
- 不在浏览器端实时 TTS；
- 不使用商业按量 API；
- 模型层可替换，但演员库、导演脚本和真题数据保持不变。

如果未来出现质量明显更高的免费开源模型，只替换生成器，不改变上层数据结构。

## 8. 自动导演系统

### 8.1 文章级导演

每篇文章先判断：

- 文章类型；
- 作者态度；
- 整体气质；
- 美式/英式语境；
- 是否存在人物和对白；
- 主旁白演员。

### 8.2 句子/片段级导演

每个句子或句内片段生成：

- `actor_id`
- `emotion`
- `intensity`
- `rate`
- `scene_id`
- `speaker_role`

换演员由角色/场景驱动，轻微语气变化只改变表演状态。

### 8.3 人工覆盖

导演结果允许人工覆盖。若试听后某一句情绪或演员判断不理想，只修改该片段的导演字段并重新生成该片段，不影响其他已通过音频。

## 9. 质量审核

每个生成片段至少过 5 类审核。

### 9.1 文本忠实度

本地 ASR 反向转写，与原文本比对，发现漏词、重复、关键词错误、数字/专名明显读错则重生成。

### 9.2 音色一致性

比较生成音频与演员参考声纹的一致性，检测明显音色漂移。

### 9.3 技术质量

检测：

- clipping/爆音；
- 异常静音；
- 过低音量；
- 句尾截断；
- 多余首尾静音；
- 突然断音等。

### 9.4 语速与停顿

结合词数、标点和句法估计合理时长。异常过快、过慢或关键标点缺乏基本停顿时标记重试。

### 9.5 影视自然度基准

替代笼统的“情绪好不好”审核。

基准方向：

- 基础自然度：`The Intern`；
- 轻松/人物/幽默：`Modern Family`；
- 观点/论述/评论：`The Newsroom`。

这些作品只作为节奏、重音、停顿、情绪幅度和自然度的参考，不作为音色克隆目标。

总体声音目标：

`教材级发音准确度 + 优秀美剧/电影式自然度 + 克制有声书式表演幅度`

### 9.6 失败重试

每个片段：

`生成 -> 自动审核 -> 通过则固化 -> 失败则换随机种子/微调参数重试 -> 最多自动重试 2-3 次 -> 仍失败则标记人工处理`

强度 `2`、角色对白、笑点和换声节点优先进入人工抽检。

## 10. 音频文件与缓存

音频以句子或句内片段为最小可替换单元，不把整篇文章做成单一大文件。

优先格式：Opus。

示意：

`audio/2002/text1/010-a.opus`

`audio/2002/text1/010-b.opus`

`audio/2002/text1/010-c.opus`

网页按 manifest 顺序连续播放，在用户听感上仍然是一句完整内容。

每个片段生成指纹至少由以下字段决定：

`text + actor_id + reference_pack_version + emotion + intensity + rate + model_version`

如果指纹未变化且音频已通过审核，则重新批处理时直接跳过。

## 11. 运行时播放

网站只读取静态 manifest 和静态音频文件。

播放时不执行：

- TTS 生成；
- AI 导演分析；
- 付费 API 请求。

因此重复播放不会增加 TTS 调用费用。

现有播放器继续支持：

- 单句播放；
- 暂停/继续；
- 上一句/下一句；
- 重播；
- 当前句高亮；
- 0.85x / 1x / 1.15x 等播放速度；
- 下滑隐藏、上滑唤回播放器。

## 12. 第一阶段实施范围

不立即生成 20 多年全部音频。

第一阶段只做 `2002 Text 1` 完整样片：

1. 对 21 句完成文章级和片段级导演脚本；
2. 只准备该文章实际需要的 3-4 个演员参考包；
3. 生成所有句子和句内对白片段；
4. 运行自动 QA；
5. 对角色切换、强情绪、笑点进行重点试听；
6. 将通过的 Opus 音频接入现有网页；
7. 用户在 vivo/Android 实机试听并确认声音质量。

只有 `2002 Text 1` 达到满意标准后，才扩展到 2002 全年；2002 全年验证通过后，再批量扩展到其他年份。

## 13. 2002 Text 1 示例导演方向

文章主体是“演讲中如何使用幽默”。

建议：

- 主旁白：05 演讲型男声；
- 普通建议句：`neutral` / `warm`，强度 0-1；
- 天堂故事进入后：更强叙事感，`lively 1`；
- 新来者的提问：年轻角色，`curious 2`；
- St. Peter：年长男性角色；
- 笑点 `but sometimes he thinks he's a doctor`：St. Peter 同一演员，`ironic 2`；
- 故事结束后返回主旁白。

该方案用于验证 B2 的三项核心能力：主旁白稳定、场景换声、句内换声。

## 14. 明确不做

第一阶段不做：

- 实时云端 TTS；
- Google API；
- 商业 TTS 按量付费链路；
- 一次性生成全部二十多年音频；
- 广播剧级背景音乐和环境音；
- 为了增加趣味而在无文本依据处强行插入儿童声或其他角色声；
- 与声音系统无关的大规模网页重构。

## 15. 成功标准

`2002 Text 1` 样片成功需同时满足：

- 所有英文内容无明显漏读、错读和截断；
- 美音为主且清晰自然；
- 主旁白前后一致；
- 角色切换逻辑清楚但不突兀；
- 句内换声连续，不破坏一句话的语义节奏；
- 笑点和故事段落明显比普通说明句更生动；
- 不因表演牺牲英语学习所需的发音、重音和句法结构；
- vivo/Android 端可稳定播放；
- 重复播放不产生 TTS API 费用；
- 若单句需要修改，只重新生成对应片段。

通过该样片后，系统进入全年扩展阶段。
